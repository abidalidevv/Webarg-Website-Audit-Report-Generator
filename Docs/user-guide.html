Webarg Operator Manual

A step-by-step technical and operational handbook for running website audits, interpreting evidence-based reports, pitching clients, and diagnosing system services.

01. Overview & Business Purpose

Webarg is an objective, deterministic website diagnostic and conversion inspection tool designed for independent developer Abid. It acts as an authoritative, high-trust diagnostic instrument to pitch and close paid $1,500 to $3,500 remediation sprints.

The Core Workflow
Enter Prospect URL → Deep Automated Scan → Verifiable Shareable Report + Branded PDF → Client Pitch → High-Ticket Remediation Sprint.

Unlike generic SEO crawlers that produce vanity metrics, Webarg focuses on hard evidence:

  • Deterministic Evidence: Specific DOM element selectors, HTTP response status codes, console error timestamps, and real Core Web Vitals measurements.
  • Revenue Impact: Pinpoints lead drop-off points such as unclickable phone numbers on mobile screens, missing form validation, or layout shifts.
  • No Synthetic Data: Real measurements only. Missing data is transparently reported as unmeasured rather than substituted with fake numbers.

02. Quick Start & Starting the App

Webarg consists of a React (Vite) client and an Express.js backend engine.

Starting the Backend Engine

cd server
node src/index.js

The backend initializes on http://localhost:5000 and is ready to process scan requests.

Starting the Frontend Client

cd client
npm run dev

Open http://localhost:5173 in your browser to access the Webarg auditor interface.

03. Running a Website Scan

1

Enter the Prospect's Website URL

Input any domain or URL in the search input (e.g. efix.ae, https://targetsite.com). If omitted, https:// is automatically prepended.

2

Choose Scan Depth

Quick (Public Checks): ~10-15s check covering DNS, SSL/TLS, HTTP response headers, robots.txt, sitemap.xml, custom 404 handler, and initial DOM structure.
Deep (Full Diagnostic): ~30-45s full inspection using headless Chromium to capture console runtime errors, failed network assets, Axe-core accessibility, and mobile layout at 320px.

3

Observe Live Inspection Animation & Progress

When you click Inspect website, the tactical oscillating wavy grid mesh and sweeping laser beam appear, displaying live progress (0% → 100%) and the current diagnostic phase.

04. Understanding Health Scores & Badges

Webarg presents five health indicators in the Executive Summary Strip:

Indicator Type Weight Description
Overall Health Aggregate 100% Weighted average across actually measured scores. Categorized as HEALTHY (80+), NEEDS ATTENTION (55-79), or AT RISK (<55).
Conversion Health Derived Heuristic Heuristic Computed from observed friction factors (critical findings drop the score by 15 pts; warnings by 5 pts). Labeled as derived so it is not confused with lab scores.
Performance & CWV Measured CWV 30% Measured via Google Lighthouse & PageSpeed. Reflects LCP, CLS, and TBT. Displays null/dash if unmeasured.
SEO & Identity Measured Spec 25% Directly checks title tags, meta descriptions, duplicate H1 headers, canonical links, and crawl signals.
Security & Headers Measured SSL/TLS 25% Validates TLS certificate validity, HSTS, CSP, X-Frame-Options, and server signature leaks.

06. 5 Real Customer Journeys

Audits five vital prospect funnels defined in Section 71 of the Webarg Playbook, distinguishing between directly measured technical signals and indirect heuristic proxies:

Journey Confidence How It Is Evaluated
Journey A — New Visitor Indirect Proxy Evaluates 5-second clarity and whether the primary Call-To-Action (CTA) is immediately visible without friction.
Journey B — Inquiring Lead Indirect Proxy Checks whether contact forms, phone links, or email channels exist in the DOM (actual message receipt requires manual testing).
Journey C — Mobile Customer Direct Signal Directly checks tap-to-call dialers and mobile layout at 320px viewport width.
Journey D — Returning User Direct Signal Validates caching headers, compression (Gzip/Brotli), and repeat performance metrics.
Journey E — Failure Recovery Direct Signal Sends a request to an intentional 404 route and verifies authentic HTTP 404 status handling.

07. Table View vs. Visual Graph View

Webarg offers two complementary presentation views:

  • Table View (Default): Provides detailed expandable accordions for each finding with exact CSS selectors, HTTP headers, code lines, user impacts, and technical recommendations.
  • Visual Graph View: Displays SVG Score Breakdown bars, a Severity Distribution donut chart, and Google PageSpeed Core Web Vitals Threshold Spectrums (LCP, CLS, TBT) with clear Good, Needs Work, and Poor benchmark zones.

08. Before & After Comparative Rescans

When you re-scan a website after making fixes, Webarg automatically compares the current scan against prior scans of the exact same domain.

Genuine Set Diff Proof
Webarg does not guess deltas. It computes a true set difference between previous and current finding headlines to show the exact count and list of Resolved Issues along with score improvements (e.g. +19 pts).

09. Sharing & PDF Export

  • GTmetrix-Style Link: Every audit report generates a permanent ID (e.g. /report/dRrnnlcJT555). Sending this URL to anyone loads the complete report without rescanning.
  • Download PDF: Clicking Download PDF in the header invokes headless Chrome to render an exact print-styled PDF report (webarg-audit-[domain]-[date].pdf).
  • WhatsApp / Email Outreaches: Footer buttons generate pre-drafted client pitch messages containing the live report link ready to send.

11. Live System Diagnostics ("Diagnose Website")

Located in the bottom-right corner of the Admin Dashboard is the floating Diagnose System button.

Clicking it triggers an end-to-end operational diagnostic across all services:

  1. Express API Server: Tests port 5000 route handling and latency.
  2. SSRF Guard & DNS: Validates DNS resolution and private network blocking.
  3. Browserless Connectivity: Verifies WebSocket connection to hosted Chromium.
  4. Gemini AI API: Confirms API key validity and deterministic fallback responses.
  5. PDF Generator: Tests Puppeteer print engine rendering.

12. Security & Rate Limits

  • Rate Limit: 5 scans per hour per IP. Express uses proxy-aware req.ip to prevent header spoofing via X-Forwarded-For.
  • SSRF & TOCTOU Protection: Blocks internal addresses (127.0.0.1, 169.254.169.254, 192.168.x.x). Browserless navigation pins the validated public IP via --host-resolver-rules to prevent DNS rebinding.
  • Read-Only Inspection: Safe, non-invasive auditing that never modifies client data.
